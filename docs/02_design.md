# 詳細設計書：交通費精算シミュレーター

本書は `docs/01_requirements.md` に基づく詳細設計である。

## 1. 要件から読み取った値

| 項目 | 値 | 出典（要件定義書） |
|---|---|---|
| 自家用車の単価 | 1kmあたり 15円 | 機能A（現行仕様。20円は「旧仕様」のため不採用） |
| タクシーの単価 | 1kmあたり 400円 | 機能A |
| 上長承認が必要となる基準額 | 10,000円 を**超える**場合 | 機能B |
| 交通手段 | 電車、タクシー、自家用車 | 機能A |
| 所属部署の選択肢 | 営業部、総務部、経理部、企画部 | 機能A |
| 申請者の入力項目 | 申請者名、所属部署 | 機能A |
| 明細の入力項目 | 利用日、出発地、到着地、交通手段（＋距離または運賃） | 機能A |
| CSVの列（順番どおり） | 利用日, 申請者名, 部署, 出発地, 到着地, 交通手段, 距離(km), 金額(円), 承認ステータス | 5章 |
| CSVの距離(km) | 電車の場合は空欄 | 5章 |
| CSVの申請者名・部署・承認ステータス | 同じ申請のすべての明細で同じ値 | 5章 |
| 利用日の形式 | 年-月-日（例：2026-10-08） | 5章 |

## 2. 採用した仮定（要件定義書に定めのない事項）

| No. | 仮定 | 理由 |
|---|---|---|
| 1 | 「電車」は距離による計算規定がないため、利用者が運賃（円）を直接入力する | 要件に単価の記載がない |
| 2 | 「タクシー」も自家用車と同様に走行距離（km）を入力させ、距離 × 400円で計算する | 「1kmあたり400円」の記載から距離入力が必要と判断 |
| 3 | 距離に小数（例：12.5km）を許可し、計算結果の1円未満は**切り捨て**る | 端数処理の規定がない |
| 4 | 合計がちょうど 10,000円 の場合は「自動承認」とする | 「超える場合」と記載されているため |
| 5 | 距離・運賃が負の値、または未定義の交通手段の場合はエラー（`ValueError`）とする | 不正入力の防止 |
| 6 | 「1回の申請」とは、画面上で入力した明細すべての合計とする | 申請単位の定義がない |
| 7 | CSVの文字コードは Excel で文字化けしない UTF-8（BOM付き）とする | 総務・経理担当者が Excel で開くことを想定 |
| 8 | 申請者名・部署は画面上部で1回だけ入力し、すべての明細に共通で適用する | 5章「同じ申請のすべての明細で同じ値」に従う |
| 9 | 利用日の初期値は当日とする | 入力の手間を減らすため |
| 10 | 申請者名が未入力の場合は、CSVダウンロードボタンを押せないようにする | CSVの申請者名が空欄になることを防ぐため |
| 11 | 選択肢にない部署を指定した場合はエラー（`ValueError`）とする | 不正入力の防止 |
| 12 | 距離が整数の場合は小数点を付けずに出力する（30.0 → 30） | 要件の例「30」に合わせる |

## 3. 定数

| 名前 | 値 | 意味 |
|---|---|---|
| `CAR_RATE_PER_KM` | 15 | 自家用車の1kmあたり単価（円） |
| `TAXI_RATE_PER_KM` | 400 | タクシーの1kmあたり単価（円） |
| `APPROVAL_THRESHOLD` | 10000 | この金額を超えると要上長承認（円） |
| `TRANSPORT_TYPES` | `["電車", "タクシー", "自家用車"]` | 選択できる交通手段 |
| `STATUS_AUTO` / `STATUS_NEEDS_APPROVAL` | `"自動承認"` / `"要上長承認"` | 承認ステータスの表示文字列 |
| `DEPARTMENTS` | `["営業部", "総務部", "経理部", "企画部"]` | 選択できる所属部署 |
| `RECORD_COLUMNS` | `["利用日", "出発地", "到着地", "交通手段", "距離(km)", "金額(円)"]` | 画面の明細一覧の列 |
| `CSV_COLUMNS` | `["利用日", "申請者名", "部署", "出発地", "到着地", "交通手段", "距離(km)", "金額(円)", "承認ステータス"]` | CSVの列 |

## 4. 関数一覧（`src/app.py`）

| 関数名 | 入力 | 出力 | 説明 |
|---|---|---|---|
| `calc_fare(transport, distance_km=0, train_fare=0)` | 交通手段（str）、距離（float, km）、電車運賃（int, 円） | 金額（int, 円） | 交通手段ごとの金額を計算する |
| `calc_total(records)` | 明細のリスト（各要素は `"金額(円)"` キーを持つ dict） | 合計金額（int, 円） | 明細の合計を求める |

| `make_record(use_date, departure, arrival, transport, distance_km=0, train_fare=0)` | 利用日（`datetime.date` または `"年-月-日"` の文字列）、出発地、到着地、交通手段、距離、電車運賃 | 明細（dict：利用日・出発地・到着地・交通手段・距離(km)・金額(円)）。利用日は `"年-月-日"` の文字列、電車の距離は `None` | 入力から1件の明細を作る |

| `main()` | なし | なし | Streamlit の画面を描画する（単体テスト対象外） |

## 5. テストで確認する値

### 5.1 `calc_fare`
| 入力 | 期待値 | 観点 |
|---|---|---|
| 自家用車, 10km | 150 | 単価15円の確認（旧仕様20円なら200） |
| 自家用車, 0km | 0 | 境界値（下限） |
| 自家用車, 12.5km | 187 | 小数距離・端数切り捨て（187.5 → 187） |
| 自家用車, 0.33km | 4 | 端数切り捨て（4.95 → 4） |
| タクシー, 10km | 4000 | 単価400円の確認 |
| タクシー, 2.5km | 1000 | 小数距離 |
| 電車, 運賃 580円 | 580 | 運賃をそのまま採用 |
| 電車, 距離100km・運賃 300円 | 300 | 電車は距離を使わない |
| 自家用車, -1km | `ValueError` | 負の距離 |
| 電車, 運賃 -1円 | `ValueError` | 負の運賃 |
| 飛行機 | `ValueError` | 未定義の交通手段 |

### 5.2 `calc_total`
| 入力 | 期待値 |
|---|---|
| 空のリスト | 0 |
| 金額(円) 150, 4000, 580 の3件 | 4730 |

### 5.3 `needs_approval` / `approval_status`（境界値）
| 合計金額 | `needs_approval` | `approval_status` |
|---|---|---|
| 0 | False | 自動承認 |
| 9,999 | False | 自動承認 |
| 10,000 | False | 自動承認（ちょうどは「超えない」） |
| 10,001 | True | 要上長承認 |

### 5.4 `make_record`
| 入力 | 期待値 |
|---|---|
| 2026-10-08（date型）、高松 → 丸亀、自家用車、30km | 利用日 `"2026-10-08"`、距離 30、金額(円) 450 |
| 利用日を文字列 `"2026-10-08"` で指定 | 利用日 `"2026-10-08"` |
| 自家用車、30.0km（画面からの入力は小数型） | 距離 30（整数） |
| 電車、運賃 580円 | 距離 `None`（CSVでは空欄）、金額(円) 580 |

### 5.5 `records_to_csv`
- 先頭が UTF-8 の BOM であること。
- ヘッダ行が `利用日,申請者名,部署,出発地,到着地,交通手段,距離(km),金額(円),承認ステータス` であること。
- 明細が空でもヘッダ行が出力されること。
- 要件の例（2026-10-08、香川 太郎、営業部、高松 → 丸亀、自家用車、30km）が `2026-10-08,香川 太郎,営業部,高松,丸亀,自家用車,30,450,自動承認` と出力されること。
- 電車の明細は距離(km)が空欄になること。
- 合計が 10,000円 を超える申請（自家用車30km 450円 + 電車 580円 + タクシー25km 10,000円 = 11,030円）では、すべての行の承認ステータスが「要上長承認」、申請者名・部署がすべての行で同じになること。
- 選択肢にない部署（例：人事部）を指定すると `ValueError` になること。

## 6. 画面構成（`main()`）
1. 最上部に「合計金額」と「承認ステータス」を大きく表示する。要上長承認の場合は「※要上長承認」を赤字で表示する。
2. 申請者情報：申請者名（テキスト入力）、所属部署（選択式：営業部、総務部、経理部、企画部）。
3. 明細の入力フォーム：利用日（初期値は当日）、出発地、到着地、交通手段、距離（km）または運賃（円）、「明細を追加」ボタン。
4. 明細一覧テーブル、「明細をクリア」ボタン。
5. 「CSVダウンロード」ボタン（申請者名が未入力の場合は押せない）。
6. 明細はセッション（`st.session_state`）に保持する。
